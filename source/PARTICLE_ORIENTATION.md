# Particle sprite orientation

Animated sprite renderers support camera-facing orientation (type 0), upright orientation (type 1), and plane orientation (type 2). Type 1 uses the installed renderer's horizontal camera-perpendicular axis and world Z, with authored roll. Type 1 orientation control points are rejected pending verification. Type 2 with orientation control point -1 uses the Source world XY plane. An explicit type 2 control point uses its imported world rotation to orient that plane; its translation does not reposition particles. Unsupported modes and missing transforms are reported as conversion limitations.

`Rotation Yaw Random` is supported only for type 2 world-XY sprites with no orientation control point and default timing/strength settings. Yaw and roll combine around the same world-Z axis. The original HL2 `water_foam_01c` PCF passed a sampled Blender bake, finite geometry, save/reopen and diagnostic particle-visibility render. Converter random streams, SFM UV/render parity and broader session integration remain unverified. Other yaw orientations and timed/shared-strength yaw remain rejected. These orientation changes are included in release 0.28.13.

Native Blender diagnostics verified world-plane geometry, camera independence, animated control-point rotation, missing-control rejection, and exact vertex persistence after save/reopen. The control-point test overrides an installed EMP wave definition for testing; that original effect uses control point -1. An isolated render also verified that the original EMP wave refraction material changes a checker background and survives save/reopen.

Type 1 geometry was traced from the installed PET mode-1 vertex helper and checked with the original Portal 2 fire_medium_01 graph and its three children: sampled bake, save/reopen and diagnostic render all passed in Blender 5.2.2. Geometry calculations also passed checks for square dimensions and invalid/degenerate axes. Camera-interface identity, exact camera input interpretation and SFM appearance/UV parity remain unverified. The current development source enables this mode with these limitations. This orientation support is included in release 0.28.13.

These checks do not establish matching Source particle simulation ticks, random streams, UV appearance, or full rendered visual parity. Diagnostic frame previews also do not establish particle birth-history control motion when earlier animation keys are omitted. Full-session validation is still required.

Scalar alpha remaps support explicit lifetime, current-alpha or creation-time input and alpha output with constant strength. They run in authored order, including chained overwrites. Other fields, missing bounds and authored strength fades remain reported as limitations. Original EMP flash and wave definitions passed native sampled geometry and alpha persistence checks, including a focused test using the original Pokémon session descriptor and source control animation. This does not prove full-scene rendering or matching SFM appearance.

A stored-installation audit found 79 records containing Remap Scalar; 10 were accepted by the planner after these changes. Duplicate records are retained, and acceptance is not a native render result. Remaining blockers include twist forces, control-point setters, trace collisions, model-position initializers and other scalar fields.
