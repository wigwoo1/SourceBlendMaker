# Experimental particle noise initializers

Enable this option for PCFs using **Remap Noise to Scalar** or **Velocity Noise**. It varies initial radius, roll, rotation speed, lifespan, primary opacity, secondary opacity, or velocity from spatial/time noise. The option is off by default and is saved with GUI preferences. It applies to single sessions and queued conversions.

For births containing Velocity Noise, ordinary initializers run first, with the first writer setting each attribute. Additive and override initializers then run in authored order. Velocity Noise samples the position available at its point in that second pass, adds motion without changing the spawn point, and uses particle creation time. Box and sphere spawning, independent component absolute/invert flags, descending output ranges, and a selected control point's local rotation are supported. Radius-scaled offsets use the radius initialized in the first pass. Source units are used before Blender scaling. Original initializer indices are preserved for sequence contexts.

Velocity Noise combinations with Position From Control Points or Position Along Path Sequential are explicitly rejected: their additional lifetime/attribute writes are not yet represented by the ordered adapter. Other unverified callbacks and non-default shared strength/time gates are also reported, not silently ignored. Effects using scalar noise without Velocity Noise keep the earlier approximate authored-order adapter; later random writes can replace those scalar noise results. This release does not change the ordinary non-experimental particle path.

The noise helper and defaults were recovered through static inspection of the installed SFM binary. The Velocity Noise scalar calculations were compared with a Python interpreter of the installed instructions: 772 core noise samples and 260 velocity cases, including all 64 absolute/invert flag pairs and local matrix rotation. Blender tests verify spawn/offset ordering, local rotation, additive motion, velocity-only noise, and saved/reopened meshes. Source random streams, emission-batch timing, physical-velocity integration versus Source position-buffer rounding, initial engine buffer state, SIMD birth batching, and exact visual parity remain unverified.

Development validation currently covers original dispenser smoke 1/2, two elevator core variants, portal-gun core glow, and water upjet B. Each produced finite geometry, saved and reopened, and contributed pixels to a diagnostic render compared with hidden particles. These tests sample 12 frames over two seconds with diagnostic control points; they do not prove full-session or SFM visual parity. The portal glow requires its authored RGB control point. The water test used actual stage_big BSP tint, with control points above the floor.

Unsupported contexts remain reported: parent/model spawning combined with noise, maintained emitters, external world-time noise, unrepresented attribute fields, and contextual initializers without ordered handlers. Map tint requires its separate option and a supported map-light query. Shared tint across renderer passes remains unsupported. The full water_upjet graph additionally uses an unsupported child ramp operator; it has not passed conversion.

Version 0.28.12 includes this option. Release checks passed 633 staged tests, packaged GUI startup, six original-effect diagnostic bakes and renders, and the full 1440-frame particle-test session save/reopen plus three sampled camera renders. These checks do not establish all-effect support or exact SFM visual parity.
